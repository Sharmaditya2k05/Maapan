# Runbook — redeploy the Render showcase demo

The showcase runs every Go service on Render's **free** plan from `render.yaml` (a Blueprint at the repo
root) and dukaan on Vercel. It is demo-only: `APP_ENV=local`, OTP `123456`, mock payments, kar's GST
simulator, messages printed to the logs. Never put real business data in it.

| Piece | Where |
|---|---|
| Services | `maapan-<service>.onrender.com` (dwaar is the only one the browser talks to) |
| Database | one free Postgres `maapan-db`, each service in its own schema (`?search_path=<service>`) |
| Redis | free Key Value `maapan-redis` (OTP, rate limits) |
| Shared env | env group `maapan-shared` (`JWT_SECRET`, `SERVICE_SECRET` generated by Render, `*_URL`, `SVC_TIMEOUT=75s`) |
| Frontend | Vercel project, root `dukaan`, `NEXT_PUBLIC_API_URL=https://maapan-dwaar.onrender.com/api` |
| Branch | services deploy from `main` (`branch: main` in `render.yaml`) |

## Routine redeploy (new code on `main`)

Render auto-deploys each service when `main` changes. To force one:

1. Render dashboard → service → **Manual Deploy → Deploy latest commit** (or *Clear build cache & deploy*
   after a `go.mod` change).
2. Deploy order only matters when an internal API or event shape changed: callee before caller, e.g.
   `pehchaan` → `bahi`/`kar` → `bhandar` → `aadesh` → `lenden` → `soochna` → `buddhi`/`aayaat`/`nirmaan`
   → `dwaar` last.
3. Migrations run on start (`AUTO_MIGRATE` default) in each service's schema.

Blueprint changes (new service, env var, plan) → Render → **Blueprints → maapan → Sync** (or *Manual sync*).
Render shows a diff; apply it. A new key in `maapan-shared` reaches every service on its next deploy.

## Wake-up and smoke test

Free services sleep after 15 idle minutes and take up to a minute to wake. Render answers calls from
*inside* Render (dwaar → service) with `502 no-deploy` while a service sleeps and does not wake it, so
wake everything from outside first:

```bash
curl -s --max-time 120 https://maapan-dwaar.onrender.com/wake     # waits until every upstream answers /healthz
curl -s https://maapan-dwaar.onrender.com/healthz
for s in pehchaan bahi kar aadesh lenden soochna aayaat bhandar nirmaan buddhi; do
  printf '%-9s ' "$s"; curl -s -o /dev/null -w '%{http_code}\n' --max-time 90 "https://maapan-$s.onrender.com/healthz"
done
```

Then in the browser: `https://maapan.vercel.app` → *Enter demo* (it calls `/wake` too) → log in with any
phone and OTP `123456` → create an item → a POS bill → check the ledger. dukaan re-pings every 10 minutes
while open.

## Database expired or broken (free Postgres lasts 30 days)

1. Render → `maapan-db` → note the expiry date in advance; when it expires every service fails `/readyz`.
2. Delete the expired `maapan-db` and **sync the Blueprint**: it declares `maapan-db`, so Render creates a
   fresh free database and the services' `fromDatabase` `DATABASE_URL`s point at it. (Check each service's
   *Environment* tab afterwards; if one still shows the old host, sync again or set it by hand.)
3. Redeploy all services (step 1 above). Each creates its schema and runs migrations on start; the
   demo starts empty — log in and onboard again.
4. If schemas exist from a half-failed run and a migration complains, drop that service's schema in the
   Render Postgres shell (`DROP SCHEMA <service> CASCADE;`) and redeploy the service. Demo data only.

## Rotating the shared secrets

`maapan-shared` → regenerate `JWT_SECRET` / `SERVICE_SECRET` → redeploy **all** services together (a
mismatch makes service-to-service calls 401). Everyone is logged out.

## Common failures

| Symptom | Cause | Fix |
|---|---|---|
| Browser: CORS error | Vercel domain not in `CORS_ORIGINS` | add it in `maapan-shared`, redeploy dwaar |
| 502 on the first action after a pause | upstream asleep | `/wake`; dwaar retries edge-rejected requests, dukaan retries GETs once |
| Build fails `cannot find module github.com/maapan/mool` | build command lost `GOWORK=off` / the `replace ../mool` | keep `cd <svc> && GOWORK=off go build …` as in `render.yaml` |
| `too many connections` | 11 services × `pool_max_conns=3` on the free Postgres | keep `pool_max_conns=3` in every `startCommand`; do not add instances |
| Events not arriving | `EVENTS_DRIVER=direct` posts to `*_URL`; target asleep | wake, then replay outbox dead rows ([outbox-dead-rows.md](outbox-dead-rows.md)) |
